# 分形文档规范

> 本文件定义分形文档的通用规范，适用于所有技术栈。

---

## _DIR.md

每个项目自有的源码、产品、规格、自动化和运行记录目录都要有一个 `_DIR.md`，用于说明：
- 这个目录负责什么
- 子目录如何分工
- 哪些文件是关键入口

要求：
- 内容使用中文
- 聚焦职责，不写重复的实现细节
- 目录结构变化时同步更新

以下目录不在此约束内：依赖与构建缓存（如 `node_modules/`、`.next/`）、版本控制内部目录（`.git/`），以及由外部工具管理或复制的目录（如 `.codex/`、`.claude/`、`.agents/skills/`）。若框架主动维护工具目录（如 `.github/`），仍应提供 `_DIR.md`。

---

## 文件头注释

关键源码文件使用如下格式：

```
/**
 * @input ...
 * @output ...
 * @pos ...
 */
```

要求：
- `@input`：文件依赖什么输入、上下文或上游模块
- `@output`：文件对外提供什么能力、结果或副作用
- `@pos`：文件在当前层级中的职责定位
- 使用英文短句

不同语言的注释语法：
- TypeScript/JavaScript: `/** ... */`
- Python: `"""..."""` docstring
- Go: `// @input ...`
- CSS: `/* @input ... */`

---

## 约束

- 实现源码与单个 `tasks.md` 不超过 300 行；长篇 guide、skill reference 和框架发行脚本可按章节组织，但不得内联大段实现代码
- 文档更新是实现过程的一部分，不是收尾动作
- 顶层结构变化时同步更新 `openspec/project.md` 的 Directory Structure
